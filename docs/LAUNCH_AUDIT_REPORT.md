## Issues found and fixed

- Replaced the thin tool-directory-style homepage with a product landing page that explains capabilities, provenance, privacy, and the future comparison model.
- Reduced the desktop header to five grouped destinations and rebuilt the footer around tools, directories, and trust pages.
- Added About, Contact, Privacy, Terms, and Methodology pages with accurate current-state language and no partnership, advertising, or legal guarantees.
- Removed empty mobile-plan entry pages from indexing and the sitemap while retaining useful user access and followable links.
- Made metadata/sitemap origin configurable and standardized production examples and structured-data URLs on `signal-rate.com`; no localhost origin appears in production metadata defaults.
- Removed a global anchor-color rule that overrode Tailwind link contrast. A 379 px browser audit then confirmed visible header text and no horizontal overflow.
- Added a keyboard skip link, consistent focus-visible treatment, a searchable 404 page, and a production-safe application error boundary.
- Added disabled-by-default ad and analytics abstractions. No ad/analytics request or fake publisher ID ships; `/ads.txt` safely returns 404 until a valid environment record exists.
- Added CSP, framing, MIME-sniffing, referrer, and permissions headers. Development alone allows eval for React tooling; production does not. HSTS is reserved for the proven HTTPS terminator.
- Added standalone/non-root production images, internal PostgreSQL/Redis, resource-bounded Redis, same-origin Nginx proxying, and health checks for all services.
- Added a root `.dockerignore`, reducing the frontend build context observed during validation from more than 550 MB to under 1 MB. Production images use distinct names so their builds cannot replace the local development backend image tag.
- Added a development-only configurable read-rate ceiling so the comprehensive local crawler can run without weakening the production default of 60 requests per minute.
- Built a repeatable route/link/status audit with timeouts; the final crawl found zero broken internal targets or unexpected redirects.

## Content, indexing, canonical, and schema review

- Tools solve an interactive task and include explanations/related flows; they are not ad surfaces.
- Error details require published source-backed content. Family/detail intent is distinct and schema uses `CollectionPage`, `TechArticle`, and breadcrumbs without fake authors/reviews.
- Country, calling-code, MCC/MNC, and carrier sitemap entries retain existing verification/content gates. Unknown fields remain unknown; concise reference pages are assessed using a lower reference-page threshold than educational articles.
- Search and parameterized/filter results remain noindex. Canonicals point to clean non-query routes and the crawler found no indexable page missing a canonical or meta description.
- Software tools use `SoftwareApplication`; site-wide `WebSite` search schema remains. No fake rating, review, or current plan offer was introduced.
- Repository/output searches found no Lorem Ipsum, placeholder descriptions, fixture operators, test plans, live publisher IDs, or production localhost metadata. Localhost remains only where appropriate for development, tests, and local audit documentation.

## Internal linking and search

Important routes are reachable through the homepage, grouped header/footer, directories, related-tool blocks, and detail breadcrumbs. Reviewed flows include country → calling code → MCC/MNC → carrier; IP → ASN/RDAP/DNS; SPF → DKIM → DMARC; JSON → YAML/CSV/XML; and errors → relevant diagnostics. Live search checks returned results for SMS, DNS, JSON, MySQL 1064, Germany, MCC/MNC 262 01, Telekom, and mobile plans without exposing unpublished plan records.

## Performance and accessibility

Heavy SQL, YAML, CSV, XML, and QR dependencies use dynamic imports only inside their tools. The production build prerenders static pages and leaves data-backed routes dynamic; no unrelated page imports those parsers. The UI uses no large hero image and Next-managed self-hosted font assets have fixed preload behavior. Ad slots render nothing while disabled, preventing empty-space layout shifts.

Browser checks at 379 px covered the homepage, SMS tool, HTTP error detail, Germany country page, MCC 262, Telekom carrier, DNS lookup, JSON Formatter, and empty UK plans. All reported `scrollWidth === viewport width`, and rendered inputs/selects/textareas had associated labels or ARIA names. Tables/code outputs retain local horizontal scrolling. Keyboard-visible focus, a skip link, live result/error regions, and labelled copy/search controls are present. Real-user LCP/INP/CLS values cannot exist before production traffic; monitor field data after launch rather than inventing scores.

## Production and AdSense readiness

The code and runbooks are ready for a controlled production deployment, but launch still requires external operational work: domain/DNS control, an Ubuntu host, secrets, Full (strict) TLS, a real contact address, proxy-range configuration, off-host backups with a restore drill, monitoring, and jurisdiction-appropriate legal review.

Both production images were built from scratch. The standalone Next.js container returned HTTP 200 on a temporary port; the non-root PHP-FPM container started and reported ready with `curl`, `pdo_pgsql`, and `redis` enabled. A first frontend build attempt encountered an external npm `ECONNRESET`; the immediate retry completed successfully with zero audited package vulnerabilities.

AdSense remains intentionally disabled. Application is premature until the public site is stable and reviewed. Later activation requires a real environment-supplied publisher ID, account-provided ads.txt line, accurate privacy update, policy-safe placements, and a Google-certified CMP for applicable EEA/UK/Switzerland traffic. Analytics likewise requires a named vendor, consent/privacy review, and adherence to the input-free event contract.
